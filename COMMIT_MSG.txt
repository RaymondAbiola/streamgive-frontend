fix: unwrap the paginated /ngo-applications response

The admin page rendered nothing at all - not the list, not its empty
state - with a healthy API and a valid signature behind it.

GET /ngo-applications returns { applications, total, limit, offset }
since pagination was added, but listNgoApplications still returned
res.json() straight through as NgoApplication[]. State therefore held
the envelope rather than an array, and both render guards read
applications.length, which is undefined on an object. `undefined > 0`
and `undefined === 0` are both false, so every branch was skipped and
the page came out blank instead of erroring.

The shape is now checked rather than assumed, so if this endpoint moves
again it surfaces as a visible error instead of an empty page.
